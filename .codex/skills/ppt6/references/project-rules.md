# Windows 后台执行

用户不希望智能体工作时弹出控制台窗口。Node 子进程设置 `windowsHide: true`；Windows Python 子进程设置 `subprocess.CREATE_NO_WINDOW`；PowerShell `Start-Process` 使用 `-WindowStyle Hidden`。优先使用 `login: false`。有 node_repl 时，通过它启动隐藏的原生 PowerShell，附带 `-NoProfile -NonInteractive -WindowStyle Hidden` 并捕获输出。用户明确请求的交互终端保持可见；不要启动隐藏窗口的看门狗或终止无关进程。

# 项目执行约束

适用于本目录及全部子目录中的任务。以下规则记录用户明确指定的 PPT 工作流程；用户在当前会话中的明确新指令优先。

## 智能体工作区

- 项目根目录以当前仓库目录为准。根目录仅保留 `AGENTS.md`、`.codex/`、`agent-workspace/`、`assets/` 和 `task/` 等项目入口；除用户明确要求外，不在根目录新建脚本、缓存、预览、测试目录或 `outputs/`。
- `agent-workspace/` 是智能体唯一的过程工作区。新写的代码、处理中间图片、素材提取结果、渲染预览、日志、临时文件和 QA 清单均放在其中，按任务建立子目录，例如 `agent-workspace/task6/`。
- `agent-workspace/legacy/` 存放旧运行目录和清理时保留的历史内容；不要为新任务把它当作默认工作目录。
- `task/` 存放任务说明、参考资料、审核稿、审核记录和正式交付物；`assets/` 存放稳定的源素材。审核稿及交付物遵守下文指定位置，过程文件留在 `agent-workspace/`。
- 移动或清理已有文件前先核查引用关系与交付记录，避免破坏已批准成果。

## 开始 PPT 任务前

- 必须阅读并遵循本文件及 `.codex/skills/ppt6/SKILL.md`，包括适用的模型检查、原始资料核对、模板分析和审核记录要求。
- 延续任务时先检查已有审核稿及用户批准记录，保留已经确认的内容、风格和范围，不重复索要已有批准。

## 图片审核阶段：必须使用 imagegen

- 用户要求“先生成图片”“审核图”“图片稿”“原理图”或修改尚未批准的 PPT 页面时，必须使用内置 imagegen 工具生成或修改该页的视觉审核稿。单页、新增页、简单线框图、系统架构图、原理讲解图均适用。
- 禁止以“简单图更适合代码绘制”“需要精确文字、公式或论文原图”“沿用现有排版脚本”为理由，绕过 imagegen。通用技能中允许代码绘制简单图形的例外，不适用于本项目的 PPT 图片审核阶段。
- 禁止直接用 Pillow、Matplotlib、SVG、HTML/Canvas、PowerPoint 截图或其他程序化排版生成整页图片，冒充 imagegen 审核稿。只调用 imagegen 生成一个装饰元素，再用代码完成整页，也不符合要求。
- 先读取论文、项目资料和模板，核实事实、公式和数值，再将准确文案、原始素材及版式约束提供给 imagegen。保持用户确认的风格，避免无依据的 AI 装饰和空泛文案。
- 代码仅可辅助提取或裁切真实素材、核对数据、处理文件，以及在 imagegen 已生成的页面基础上修正不准确的文字或公式、嵌入准确的原始证据图。不得借局部修正重新用代码构建整页。涉及图像编辑时同时遵守当前工具的编辑要求。
- 论文图、实验图、设备照片和第三方 logo 必须有真实来源；不得让 imagegen 重画或编造图表数据并当作研究证据。生成视觉与原始证据须明确区分。
- 如果内置 imagegen 不可用或生成失败，说明具体原因，不得静默换成代码绘图。只有用户明确选择或已授权的替代生成路径才可采用；未获得该授权时保留任务待处理。
- 审核稿保存到相应任务的“审核”文件夹。记录实际生成方式、最终提示词、生成文件来源、引用素材及后处理内容，不得把程序绘图标记为 imagegen。

## 人工审核与可编辑 PPT

- 图片生成后先展示审核稿，等待用户明确批准对应页面；批准前不得制作、替换或新增该页的正式可编辑 PPT。
- 用户要求修改时，回到 imagegen 图片审核阶段，仅修改指定范围。用户对其他页面的批准继续有效。
- 审核通过后再将批准版式重建为可编辑 PPT：文字、线框、连接线、表格和可编辑图表优先使用原生对象；论文图及真实图片作为独立、可替换的图像对象嵌入。
- 禁止把整页审核图作为背景来冒充可编辑 PPT。最终须实际渲染检查，并核查对象可编辑性。
- 不主动堆积 v1/v2 等交付版本；遵循用户已有的版本清理要求，不误删原始资料或已批准成果。

## 箭头与小图标：正式 PPT 的强制规范

- 所有自行制作的流程箭头和关系连线必须使用 PowerPoint 原生连接符。直线使用直线连接符，转折和回路使用原生肘形连接符；禁止用细矩形、分离线段与三角形拼接箭头。
- 存在流程节点时，连接符应连接到节点的合适连接点；统一线宽、箭头大小与端点间距，避免穿字、穿框、方向错误和多余转折。不能仅以“可编辑”为由保留粗糙的拼接箭头。
- 检查全部交付页中的自行制作箭头，不只检查最近新增的一页；同内容的单页版、合并版和其他交付版必须同步更新。
- 装饰性或概念性小图标、示意标记及原创 logo 必须由 imagegen 生成，作为独立、可替换的图像对象嵌入。禁止用 Python、SVG、原生形状拼接或其他代码绘图手工替代这些小图标；也禁止换用现成图标库来绕过 imagegen。
- 同一套小图标须保持一致的线条、颜色、视觉尺寸和背景处理。可以用 imagegen 生成图标网格，再裁切为独立素材；保留提示词、生成来源及裁切记录。
- 图标规范不要求把有实际语义的流程结构、连接符、公式、数据表格或图表栅格变成图片。这些继续使用原生可编辑对象。论文图、真实照片和官方第三方 logo 保持原始来源，不伪造为生成图。
- 用户明确要求直接优化已交付 PPT 的箭头或替换小图标时，按已授权范围完成替换、同步交付文件并检查，无需重复索要整页审核批准；页面内容或整体版式的新增设计仍遵守图片审核流程。
- 最终检查须在 PowerPoint 实际渲染，并核实原生连接符和独立图标图像确实存在；不得只改预览 PNG 或生成脚本而漏改 PPTX。

## 提交审核图前自查

1. 本页是否确实通过 imagegen 生成或修改，且保留了生成依据？
2. 是否核对文字、公式、数值和原始图源，修复明显生成错误？
3. 是否符合现有模板及用户确认的风格，文案是否简洁？
4. 是否已保存到任务审核文件夹，并保持待审核状态？
